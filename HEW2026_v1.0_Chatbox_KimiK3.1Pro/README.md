# HEW2026 v1.0 — Chatbox / Kimi K3.1 Pro 版

`../設計・要件` の **2026/10/26 仕様決定事項（Q1〜Q45）** を優先した独立実装です。
サイト上で制限時間付きの絵を描き、正式保存した作品をポイント制オークションへ出品できます。
v1.0 では取消・再出品・制作配信・コメント・管理者操作を追加しています。

## 起動

```powershell
cd HEW2026_v1.0_Chatbox_KimiK3.1Pro
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
# .env の SECRET_KEY と開催日時を環境に合わせて変更する
python -m flask --app main.py init-db
python -m flask --app main.py seed-tags
python main.py
# http://127.0.0.1:5000
```

既定 DB は `instance/hew_v1.db` の SQLite です。XAMPP / MariaDB では `.env` の
`DATABASE_URL` を `mysql+pymysql://...@127.0.0.1:3306/hew_v1?charset=utf8mb4` に変更し、
空の DB を作ってから初期化します。本番相当のスキーマ変更は Flask-Migrate で管理してください。
パスワード、接続情報、SECRET_KEY をソースへ直書きしないでください。

### デモデータ

```powershell
python -m flask --app main.py seed-demo
# プロンプトにローカル専用パスワード（8文字以上）を入力
```

`sample1`（作者）、`sample2` / `sample3`（入札者）、`admin`（管理者）と作品3点を作ります。
CLI には復旧コードが一度だけ表示されます。デモデータは1回だけ投入できます。

## 実装範囲

| 分野 | 実装 |
| --- | --- |
| 認証 | ユーザー名・パスワード、表示名編集、復旧コードのハッシュ保存・一回使用・パスワード確認付き再発行。メール不使用 |
| Canvas | 1,024×1,024px、10/30/60/300秒、最大10レイヤー、表示・順序・不透明度、Gペン/丸ペン/ぼかし/消しゴム、直近50操作Undo/Redo |
| 途中復元 | ペンを離す・レイヤー操作時にIndexedDB保存。サーバー期限は延長せず、同じブラウザでレイヤーと履歴を復元 |
| 正式保存 | 合成PNG（5MiB以下）と全レイヤーZIPを両方検証・保存。各PNG/展開後合計容量・層数・寸法・構成情報を確認。固定後60秒再試行、成功後に一時データ削除 |
| 出品 | 下書きからタイトル・説明・既存タグ・開始価格・5/10/15/20分を設定して即時開始。イベント期限を超える出品を拒否 |
| 手動入札 | 商品詳細内で入力→確認→確定。確認後の価格変動を拒否。自己入札・終了後・残高不足を拒否 |
| ポイント | 入札時消費、高値更新時に未返還分返還、自己増額は差額消費、落札額を手数料なしで出品者へ加算。取引と通知に冪等キー |
| 自動入札 | 設定直後に判定、1pt単位の必要額、同額上限は設定順、上限変更/停止、残高不足で停止・通知。上限全額は事前確保しない |
| 終了 | CLI/商品詳細表示で期限到達分を確定。落札/未落札、出品者への加算・通知を重複なく処理。落札時の再引落しなし |
| 取消・再出品 | 無入札なら作者取消、管理者は理由必須で取消・未返還分返還・自動入札停止。取消/未落札は新しいLotとして再出品し旧履歴を保持 |
| 公開管理 | 管理者の理由付き非公開/公開復帰。開催中の非公開化は取消・返還。落札後の非公開は作者・落札者・管理者だけ閲覧可能 |
| 制作配信 | 1作品1配信、画像なし下書きと同時作成、配信前/配信中/中断/終了、中断10分と描画期限による復帰制限、完成/期限と連動終了 |
| コメント | ログイン済み・配信中のみ、200文字・空白不可・同ユーザー3秒1件、本人削除/配信者・管理者非表示、編集なし |
| コメント監査 | 削除・非表示本文を即時公開除外。最初の操作からJST暦月1か月後に本文消去（同日なしは月末）、期限後は管理者へも返さず監査記録のみ保持 |
| 検索・保存 | キーワード、複数タグAND検索、作品とオークションの別々のお気に入り |
| 補助画面 | アプリ内通知・既読、ボーナス条件/履歴、課金・支払いは遷移先のみ（Stripe通信なし） |
| 運用 | UTC保存/JST表示、開催・終了・停止目安を環境変数で設定。終了後も閲覧/ログイン/取得を提供 |

### 制作配信の位置付け

この版は正式なWebRTC方式を未選定という仕様を勝手に確定せず、**開発用Canvasスナップショット中継**を実装しています。
作者の合成Canvasを約1秒ごとにPNGで送り、閲覧側は約1秒ごとに状態・画像・コメントを更新します。
カメラ・マイク・録画はありません。接続方式、共有範囲、切断検知秒数の正式選定と負荷検証は今後の課題です。
大量同時接続向けの映像配信基盤として検証済みではありません。

## 主要画面

- `/`：開催中の競売・制作配信
- `/artworks/draw`：描画時間の選択
- `/streams/prepare`：制作配信の準備
- `/auctions/<id>`：入札・自動入札・履歴・取消・再出品への導線
- `/search`：公開作品・タグAND検索
- `/account`：下書き/履歴/お気に入り/ポイント/復旧コード再発行
- `/notifications`・`/points/bonus`：通知とボーナス
- `/admin`・`/admin/comments`：管理者の公開・取消・コメント監査

## 定期処理

```powershell
python -m flask --app main.py close-auctions
python -m flask --app main.py close-stale-streams
python -m flask --app main.py purge-comment-bodies
```

Windowsタスクスケジューラから定期実行します。再実行しても加算・返還・通知を重複しません。
アプリ停止後も、最後のコメント本文消去コマンドを運用してください。

## テスト

```powershell
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD = '1'
python -m pytest
```

15件：手動入札/差額/返還/終了/重複処理/自動入札/取消/再出品、配信状態/復帰、
コメント権限/連投/JST月末の消去、登録とPNG+ZIP保存、公開ページを検証します。
`PYTEST_DISABLE_PLUGIN_AUTOLOAD` は、マシン全体のAI関連pytestプラグインを読み込まないための設定です。
同時20人・100登録・2秒応答、スマートフォンの大容量復元、DB競合負荷は**実機検証がまだ必要**です。

## 構成

```text
main.py / app/config.py / app/commands.py
app/models/       ユーザー・作品・複数Lot・入札・配信・コメント監査
app/services/     取引・取消・画像/ZIP・配信・コメント・イベントの業務処理
app/*/routes.py   Blueprintの画面・API・認可
app/templates/    日本語のJinja2テンプレート
app/static/       独自CSS・Canvas・IndexedDB・3秒/1秒更新JS
tests/            開発DBから分離されたSQLiteテスト
```

公開PNGと配信プレビューには閲覧制限付きルートを使い、原寸PNG・全レイヤーZIPは
作者/落札確定者/管理者のダウンロード経路に限定しています。`instance/uploads` は静的公開しません。
