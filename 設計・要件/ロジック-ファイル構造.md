# ロジック・ファイル構造

2026/10/26更新：[仕様決定事項](仕様決定事項-2026-10-26.md)を優先する。本書の構成図は配置の方針であり、新設予定の認証・作品・レイヤー・ポイント・通知・イベント用サービスは実装時に追加する。コード・SQLは未変更。

## 1. 実装方針

FlaskのApplication FactoryとBlueprintを使用し、画面処理・業務ロジック・DBモデルを分離する。段階ごとに機能を追加し、初期段階は開発用ユーザーで出品者を固定する。認証実装後はログイン中のユーザーを出品者として使用する。

2026/10/20追記：出品取消・再出品・制作配信・コメントの追加仕様は[要件定義書6章](要件定義書.md)に従う。以下の追加ファイル・処理は実装予定であり、現行コード・DB設計書・SQL・ER図の変更済みを意味しない。

実装順:

1. 作品作成・出品
2. 入札・落札
3. タグ検索
4. ユーザー名によるログイン認証・復旧コード
5. 作品/オークションのお気に入り
6. 出品取消・再出品
7. 制作ライブ配信・コメント

## 3. 機能別の処理

### 3.1 作品作成・出品

1. 描画画面でJavaScriptのCanvasを操作する。ペン種類はフロントエンドの設定一覧で管理し、Gペン・丸ペン・ぼかしなどを追加できる構成にする。
2. Canvasは1,024×1,024px、最大10レイヤーとする。ペンを離した時点とレイヤー操作完了時に、レイヤー構成・直近50操作の履歴をIndexedDBへ保存する。同じブラウザで復元し、サーバー管理の期限は延長しない。完成・期限で画像を固定し、合成PNG（5MiB以内）と全レイヤーZIPを60秒の猶予内に送信する。両方保存して正式保存成功とする。公開用画像以外は認可付きダウンロード経由で返す。
3. `artworks`へ`draft`作品を作成する。制作配信で先に下書きを作った場合は、その作品へPNGを保存し、作品を重複作成しない。初期段階は開発用ユーザーを作者として使用し、認証後はログインユーザーを使用する。
4. 作者はアカウント画面の下書き一覧から出品設定へ進む。タイトル・説明・タグ・開始価格・開催時間（5・10・15・20分、初期値10分）を設定すると、作品を`listed`へ更新して`auctions`を`active`で作成する。
5. 下書き管理画面は作者だけが閲覧でき、PNG保存後は加筆を認めず、出品情報だけ編集できる。出品には画像が必要。追加仕様の制作配信とコメント閲覧は下書き管理とは別の公開経路とする。

### 3.2 入札・落札

1. 商品詳細画面内のフォームで入札額を受け付ける。別の入札画面へは遷移しない。
2. `auction_service`は`auctions`、入札者`users`、前最高入札者を`SELECT ... FOR UPDATE`でロックする。
3. オークションが`active`、終了前、自己入札でない、入札額が現在価格より大きい、残高が十分という条件を検証する。
4. 受理時は新しい`bids`行を追加する。最高入札者自身の増額は差額、それ以外は入札額を減算して`wallet_transactions`へ履歴を追加する。別ユーザーによる高値更新では前最高入札者の未返還額を返し、返還履歴を記録する。
5. 同一トランザクションで`auctions.current_price`を更新する。成功後は商品詳細画面を再表示する。
6. `flask close-auctions`を定期実行し、落札者・落札入札・確定額と出品者への全額加算（手数料なし）を一度だけ記録する。確定までは結果待ち表示とし、成功後に落札者へPNG・レイヤーZIPのダウンロードを許可する。

### 3.3 タグ検索

1. `flask seed-tags`でタグマスタを登録する。
2. 出品設定では既存タグを複数選択し、`artwork_tags`へ関連を保存する。同じタグの重複付与は許可しない。
3. 検索で複数タグを指定した場合は、選択タグ数と一致するタグ関連を持つ作品だけを返す（AND検索）。

### 3.4 認証・権限

- 新規登録はユーザー名・パスワードを必須とし、メールアドレスは一切使用しない。
- ユーザー名とパスワードでログインする。パスワードはWerkzeugでハッシュ化し、Flask-Loginでセッションを管理する。
- 描画、出品、入札、お気に入り、下書き閲覧はログイン必須とする。追加機能の配信操作・コメント投稿と削除・非表示・取消・再出品も認証と操作権限を検証する。ゲストは公開作品・タグ検索に加え、制作配信と公開コメント履歴を閲覧できる。
- 状態を変更するすべてのPOSTフォームはFlask-WTFのCSRF対策を適用する。

### 3.5 お気に入り

- `bookmarks`はオークション、`artwork_bookmarks`は作品専用とする。
- 商品詳細画面のPOSTフォームで登録・解除する。各テーブルの一意制約により重複登録を防止する。
- アカウント画面では作品とオークションのお気に入りを分けて表示する。

### 3.6 出品取消・再出品（追加予定）

1. 出品者は商品詳細から取消確認へ進む。管理者は管理画面から理由付きで取消を実行する。入札者向けの入札取消操作は設けない。
2. 入札・終了処理と共通のロック順序で対象オークションをロックし、開催中かつ終了日時前であることをサーバー側で確認する。本人の取消は受理済み入札が0件の場合だけ許可する。管理者は理由を必須とする。
3. 取消状態、操作者・日時・理由を記録し、自動入札を停止する。管理者による取消では、入札で差し引かれた未返還分だけを全額返還し、残高と返還履歴を同一トランザクションで更新する。返還済みの過去入札を復活・再引落ししない。
4. 再送時は完了済みの結果を扱い、再返還しない。ロック取得後に最新状態を検証し、入札・終了確定との競合時に両方が成立しないようにする。終了日時以降は終了処理に委ねる。
5. 再出品では作品をロックし、作者本人、取消済みまたは未落札終了、落札済みでない、開催中の別オークションがない、画像保存済みという条件を確認する。新しいオークションを作り、過去のオークション・入札履歴は保持する。
6. 商品詳細は対象オークションを識別して表示し、再出品しても旧履歴へのリンクが新しい出品へ置き換わらないようにする。

### 3.7 制作ライブ配信（追加予定）

1. 作者が配信準備画面で画像未登録の下書き作品を作成し、その作品専用の配信を1件作る。既存の未保存作品を使う場合も作者の所有権と配信の未作成を確認する。作品と配信は1対1とし、同時要求でも重複作成を防ぐ。
2. 作者本人だけが配信前から配信中へ遷移できる。閲覧はゲストにも許可するが、非公開の下書き管理情報は返さない。
3. 接続切断を検知すると一時中断と中断開始時刻を記録し、コメント投稿を停止する。再接続は中断から10分以内かつ描画期限前・イベント終了前・未終了の場合のみ、同じ配信を配信中へ戻す。
4. `flask close-stale-streams`を定期実行し、中断10分超・描画期限・イベント終了に達した配信を自動終了する。復帰要求時にも期限を確認し、定期処理の実行待ちでも期限超過後の復帰を許可しない。
5. 作者の明示終了と自動終了は終端状態とする。復帰・明示終了・自動終了は対象配信をロックして処理し、終了済み配信を再開しない。再出品でも配信を追加しない。
6. 既存の描画時間制限と保存後の加筆禁止を維持する。完成時のPNGは同じ下書きへ保存し、出品設定へ進める。描画期限・途中完成で配信も終了し、作品保存失敗でも再開しない。配信終了そのものでは出品・落札を確定しない。
7. 録画は保存しない。共有範囲・映像転送方式・接続／切断検知の方法と秒数は未決として技術選定時に再検討し、配信状態の業務ロジックから分離する。

### 3.8 配信コメント・保存期限（追加予定）

1. 投稿時は認証と配信中であることをサーバー側で検証する。状態判定と投稿保存を配信終了処理と整合させ、中断・終了後の投稿を受け付けない。本文はHTMLとして実行せずエスケープして表示する。
2. 本人の削除、配信者・管理者の非表示を権限チェック付きで処理する。編集機能は設けない。操作した時点から一般向けの一覧・履歴・リアルタイム配信に本文を含めない。
3. 操作者・日時・理由を監査記録に残す。本人削除も操作種別を記録し、任意の自由記述を必須とする仕様は追加しない。削除・非表示本文は管理者にだけ閲覧を許可する。
4. 最初の削除・非表示日時から暦月で1か月後を本文消去期限とする。翌月に同日がない場合は月末の同時刻とする。UTCで時刻を保存し、日本時間を基準に暦月を計算する。再操作で期限を延長しない。
5. `flask purge-comment-bodies`を定期実行して期限到達済みの本文を消去する。処理待ちでも期限到達後は管理者にも本文を返さない。操作記録に本文を複製せず、監査記録は本文消去後も保持する。
6. 通常コメントは配信終了後も公開履歴として保持し、1か月消去の対象にはしない。終了後の画面はコメント履歴を提供し、録画再生や新規投稿を提供しない。

## 4. DB・設定・テスト

- スキーマはFlask-Migrateで管理する。開発用ユーザーと初期タグはFlask CLIから登録する。
- `SECRET_KEY`、MariaDB接続URL、アップロード先、画像上限は`.env`で管理し、`.env.example`にはキー名と例だけを記載する。
- 自動テストは開発DBと分離した専用MariaDBで実行する。
- 最低限、PNG保存、下書きの権限制御、出品、入札/返却、落札確定、タグAND検索、ユーザー名認証・復旧コード、お気に入り登録/解除をテストする。
- 追加機能では、取消・入札・終了の競合、取消再送時の二重返還防止、再出品の同時開催防止、1作品1配信、10分境界での復帰と終了の競合、コメント権限と1か月の本文消去を検証する。
- 新しい定期コマンドもWindowsタスクスケジューラから実行する。DB設計への反映は別作業とし、現行の作品・入札の一意制約や画像必須制約が追加仕様に未対応であることに注意する。

## 5. 2026/10/26合意による処理の具体化

- 出品は選択した開催時間をイベント終了まで確保できる場合だけ受け付ける。自動延長しない。
- 入札はロック取得後のサーバー時刻で締め切り、最小1pt上乗せ。手動確認後の価格変動は再確認、最高入札者自身の増額は差額消費とする。
- 自動入札は設定直後から判定し、上限全額を確保しない。必要残高を設定時と実行時に確認し、不足で停止・通知する。上限変更・停止でも受理済み入札を維持する。
- ボーナスは自動付与。登録1,000pt・初出品300pt・正式保存100ptの条件と回数は仮データとして再検討する。
- 復旧コードはハッシュ保存し、パスワード再設定で使用後無効化。ログイン中の再発行ではパスワード確認と旧コード無効化を行う。
- 未落札・取消済みは公開履歴に残し、画像を編集せず再出品する。管理者の理由付き非公開化では開催中の競売を取消・返還し、非公開中は再出品させない。
- コメントは200文字以内・空白のみ不可・同じユーザーは3秒に1件。価格・入札履歴・通知は3秒以内、コメントは1秒程度での更新を目標とする。
- 通知はアプリ内のみ。対象・契機は[仕様決定事項8章](仕様決定事項-2026-10-26.md)に従う。
- イベント終了で新規登録・描画開始・出品・再出品・配信開始を停止し、約2時間後の停止までは閲覧・ログイン・ダウンロードを提供する。
- 終了後もデータを保持し、アプリ停止後も期限付きコメント本文の消去処理を実行する。
- レイヤーZIP・描画失敗・ダウンロード権限・仮性能条件の詳細と確認条件は[仕様決定事項](仕様決定事項-2026-10-26.md)に従う。
