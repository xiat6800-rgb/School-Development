# 仕様決定事項（2026/10/26）

本書は仕様確認Q1〜Q45で合意した内容を記録する。既存資料と異なる場合は本書を優先する。
基本機能と、取消・再出品・制作配信・コメントの追加仕様を設計対象とする。実課金・NFT・吊り上げbotは対象外。
本書は設計であり、コード・SQL・DBの移行が完了したことを示さない。旧実装用フォルダは参照対象外とする。

## 1. 認証・アカウント復旧（Q7・Q15）

- 登録・ログインは一意のユーザー名とパスワードを使用する。メールアドレスは登録・認証・通知を含め一切使用しない。
- 表示名はユーザー名とは別に管理する。
- 登録時に復旧コードを一度表示し、サーバーにはハッシュだけを保存する。
- ユーザー名と復旧コードでパスワードを再設定できる。使用したコードは無効化する。
- ログイン中は現在のパスワードを確認して復旧コードを再発行でき、旧コードを無効化する。
- パスワードと復旧コードの両方を失った場合は復旧できないことを登録時に表示する。

## 2. 描画・途中復元（Q5・Q12・Q13・Q18・Q26・Q32）

- 制限時間は10秒・30秒・1分・5分から選び、サーバーで開始時刻と期限を管理する。開始後の変更は不可。
- 通信切断・再読み込み中も時間は進む。キャンバスは1,024×1,024px固定で、端末に合わせて表示だけ縮小する。
- 最大10レイヤー。元に戻す・やり直す履歴は作品全体で直近50操作までとする。
- レイヤーの追加・削除・順序・表示状態・不透明度変更も履歴に含める。
- ペンを離した時点とレイヤー操作完了時に、作品ID・期限・レイヤー・編集履歴をIndexedDBへ一時保存する。1秒ごとの定期保存は採用しない。
- 同じブラウザで復元し、別端末への引き継ぎは提供しない。ブラウザデータ削除や保存失敗時の復元は保証しない。
- 期限到達または完成操作で描画を停止し、完成データを固定する。期限後の復元でも加筆を認めない。
- 固定後は保存だけ60秒間再試行できる。描画期限後の猶予中の加筆を完全に検証する仕組みまでは求めない。
- 猶予を過ぎても保存できない作品は出品不可・描画ボーナスなし。固定画像の端末保存を提供するが、後日のアップロードは認めない。

## 3. 正式保存・受け渡し（Q3・Q33・Q35〜Q40）

- 合成済みPNGとレイヤー付きZIPの両方をサーバーへ保存できた時点で正式保存成功とする。
- ZIPは各レイヤーのPNGと、名前・順序・表示状態・不透明度を記した構成情報を含むアプリ独自形式とする。外部編集ソフトとの直接互換は保証しない。
- 非表示レイヤーも含め、完成時の全レイヤーを渡すことを出品確認画面に明示する。元に戻す・やり直す履歴は渡さない。
- 正式保存後はアプリ内で加筆・レイヤー編集・データ差し替え不可。サーバーへの両データ保存成功後に端末の一時画像・レイヤー・編集履歴を削除する。
- 作者と落札確定済みの落札者に、原寸PNGとZIPの両方のダウンロードを許可する。公開用画像は一般閲覧を継続する。
- 公開画像の複製を完全には防止しない。手元での編集は可能だが、編集結果の再アップロード・再出品は提供しない。
- 合成PNGの上限は5MiB。レイヤーPNGは各5MiB、展開後合計50MiBを仮上限とし、ZIPの圧縮後サイズだけでは判定しない。
- ダウンロードはアプリ停止まで提供し、停止後の常時提供は対象外。取得可能時間を利用者に明示し、運営はデータを保持する。

## 4. 出品・入札・落札（Q2・Q9〜Q11・Q14・Q16・Q17・Q19・Q28・Q30・Q43）

- 出品時に5分・10分・15分・20分から開催時間を選ぶ。初期値10分。出品確定時に即時開始する。
- イベント終了までに選んだ開催時間を確保できない出品・再出品は拒否する。残り5分未満ならすべて不可。
- 開始価格は0以上の整数pt。現在価格は開始価格から始まり、入札は現在価格＋1pt以上とする。
- 終了直前の入札でも自動延長しない。ロック取得後のサーバー時刻が終了日時以上なら、クリック時刻にかかわらず拒否する。
- 手動入札の確認時から現在価格が変わった場合は、そのまま受理せず再確認を求める。
- 入札時にポイントを消費し、高値更新では前最高入札者の未返還額を返す。最高入札者自身の増額は差額だけを消費し、その差額で残高を判定する。
- 自動入札は設定直後に判定し、必要な額だけ1pt単位で競り上げる。同額の上限なら先に設定したユーザーを優先する。
- 上限額全額を確保しない。設定時点で次の入札に必要な残高（最高入札者なら差額）を必須とし、上限額自体は残高を超えてよい。
- 実行時に残高不足なら自動入札を停止し、本人に通知する。
- 上限変更・停止は可能。ただし受理済み入札は維持し、上限を現在の受理済み入札額より低く変更することは拒否する。
- 期限到達でフォームを無効化し「終了・結果確定待ち」を表示する。入札なしなら未落札、入札ありなら最高入札者を落札者として確定する。最低落札価格は使わない。
- 落札確定時に出品者へ落札額全額を手数料なしで加算し、取引履歴を残す。落札者への二重引落しはしない。
- 確定処理成功後に落札者のダウンロードを許可する。再実行でも加算・返還・通知が重複しないようにする。

## 5. ボーナス（Q4・Q8：仮データ）

自動付与方式は確定。次の量・条件・回数は仮データとして保存し、将来再検討する。受け取り操作は不要とする。

| 契機 | 仮の付与量 | 仮の条件・回数 |
| --- | --- | --- |
| 登録成功 | 1,000pt | 1アカウント1回 |
| 初出品成功 | 300pt | 1アカウント1回。「初投稿」は初出品 |
| 描画の正式保存成功 | 100pt | 日本時間の暦日で1日1回 |

同じ作品でも描画保存・初出品の両条件を満たせば両方付与する。再送で重複付与しない。画面では条件と獲得履歴を表示する。

## 6. 公開・取消・再出品（Q6・Q21・Q25・Q44）

- 一度公開した作品・過去の競売・入札履歴は保持する。未落札終了・取消済みも公開履歴として表示し、下書きへ戻さない。
- 出品者本人の取消は開催中・終了前・受理済み入札なしの場合だけ。管理者は終了前なら入札後も理由付きで取消可能。
- 管理者取消では未返還ポイントだけ全額返し、自動入札を停止する。入札者自身の個別入札取消は提供しない。
- 作者は取消済み・未落札終了作品を新しい競売として再出品できる。落札済み・同時開催・画像未保存・非公開作品は不可。画像・レイヤーの再編集は不可。
- 管理者は理由付きで作品を非公開にできる。開催中なら競売全体を取り消して未返還分を返す。
- 落札後の非公開化では取引結果を変えず、作者・落札者・管理者だけに閲覧を許可する。
- 管理者は理由付きで公開を戻せるが、取消済み競売は再開しない。再出品は通常条件で判定する。

## 7. 配信・コメント（Q23・Q24・Q29・Q34・Q41・Q42）

- 1作品1配信、配信操作は作者だけ。公開配信・公開コメント履歴はゲストも閲覧できる。下書き管理情報は公開しない。
- 配信前・配信中・一時中断・終了を区別する。切断から10分以内でも描画期限前かつ未終了の場合だけ復帰できる。
- 描画期限、途中の完成操作、作者の明示終了、イベント終了で配信を終了する。10分超の中断でも自動終了する。
- 描画・配信終了後は、PNG等の保存が失敗しても描画・配信を再開しない。再出品しても配信枠は増えない。
- 投稿はログイン済み・配信中のみ。1件200文字以内、空白のみ不可、同じユーザーは3秒に1件まで。
- 本人削除と配信者・管理者の非表示を提供し、編集は提供しない。本文は即座に公開対象外とする。
- 非公開本文は最初の操作から日本時間基準の暦月で1か月後に消去する。同日がなければ月末同時刻。再操作で期限を延長しない。
- 期限前は管理者だけが本文を参照できる。期限到達後は消去処理待ちでも返さない。通常コメントと本文を含まない監査記録は保持する。
- 競売価格・入札履歴・通知は3秒以内、コメントは1秒程度で更新する目標とする。録画保存・再生は対象外。
- **未決（Q42）：共有範囲、配信接続方式、接続・切断検知の方法と秒数。** キャンバス限定・カメラやマイクなしとは確定しない。技術選定・実機検証時に再検討する。

## 8. アプリ内通知（Q20）

| 契機 | 通知対象 |
| --- | --- |
| 入札受付 | 出品者 |
| 高値更新 | 前最高入札者 |
| 落札確定 | 落札者・出品者 |
| 未落札終了 | 出品者 |
| 出品取消 | 関係する出品者・入札者 |
| 残高不足による自動入札停止 | 設定者本人 |

確定前に成功通知を生成しない。一覧・既読状態・対象競売へのリンクを提供し、自分の操作結果は操作画面にも表示する。メール通知は提供しない。

## 9. 1日開催・終了後の運用（Q22・Q27・Q31・Q40）

- 開催日時は設定で変更できるようにする。イベント終了とアプリ停止は別の時刻とし、停止目安は終了の約2時間後。
- イベント終了で新規登録・描画開始・出品・再出品・配信開始を停止する。残っている配信を終了し、競売の確定を完了させる。
- イベント終了後も停止まではログイン・閲覧・ダウンロード可能。競売をイベント終了で途中打ち切りせず、出品時に開催時間を確保する。
- 最後の確定処理が完了してから運営が停止する。DB・作品・取引履歴・監査記録は一括削除せず保持する。
- 停止後も期限付きコメント本文の消去処理を実行できる運用を準備する。

## 10. 未決・仮値・未実施の区別

| 区分 | 項目 | 次の対応 |
| --- | --- | --- |
| 未決・技術検証 | 配信共有範囲・接続方式・接続／切断検知 | 技術選定時に再検討 |
| 仮データ | ボーナスの量・条件・回数 | 将来再検討 |
| 仮上限 | レイヤーPNG各5MiB・合計50MiB | スマートフォンで保存・復元を検証 |
| 仮性能目標 | 登録100人・同時利用20人、通常操作2秒以内 | 負荷試験。配信数の負荷は別途測定 |

| 設計反映待ち | SQL・DBモデル・ERの新スキーマ | メール廃止、複数入札、再出品、制作セッション、レイヤー、復旧コード、返還・通知の重複防止を設計・移行 |
