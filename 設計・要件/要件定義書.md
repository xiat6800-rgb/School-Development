## 2. プロジェクト概要

ユーザーが制限時間内にサイト上で絵を描き、PNGとレイヤーZIPの下書きとして正式保存した後、任意のタイミングで出品する。オークションは出品時に開始し、設定した終了日時まで開催する。描画の終了とオークションの終了は別の処理とする。

ユーザー登録・初投稿・描画などの操作に応じてボーナスポイントを付与し、そのポイントで入札する。Ver0.5ではStripe連携や実際の課金処理を行わない。

## 3. 基本的な利用の流れ

1. ユーザー名・パスワードで登録し、ユーザー名とパスワードでログインする。
2. 描画時間を10秒・30秒・1分・5分から選んで描き始める。
3. 時間切れ、または途中の完成操作で描画を終了し、PNGを下書き保存する。
4. 作者が下書きから出品設定へ進み、タイトル・説明・タグ・開始価格・開催時間を設定して公開する。
5. 他のユーザーが商品詳細画面で入札する。手動入札に加え、上限額を指定した自動入札を利用できる。
6. 終了日時で入札受付を終了し、入札があれば最高入札者を落札者として確定する。入札がなければ落札不成立とする。

## 5. Ver0.5の機能要件

### 5.1 アカウント・認証

- 新規登録ではユーザー名・パスワードを必須とする。ユーザー名は一意とする。
- ユーザー名とパスワードでログインし、ログアウトできる。
- 表示名はユーザー名とは別に管理し、初期値を設定したうえで後から編集できる。
- メールアドレスは一切使用しない。登録時に復旧コードを一度表示し、ハッシュで保存する。ユーザー名とコードでパスワードを再設定し、使用後はコードを無効にする。
- ログイン中はパスワード確認でコードを再発行できる。パスワードとコードを両方失った場合は復旧不可と登録時に明示する。

### 5.2 描画・下書き保存

- Canvas上で絵を描き、色やペンを変更できる。
- 描画開始前に制限時間を10秒・30秒・1分・5分から選択できる。開始後は制限時間を変更できない。
- 時間切れで描画を停止し、PNGを下書き保存する。制限時間内でも完成操作で終了・保存できる。
- 保存後は絵への加筆を認めない。タイトルなどの出品情報は編集できる。
- 下書きは作者だけが閲覧でき、アカウント画面の下書き一覧から出品設定へ進める。
- 1,024×1,024px、合成PNG5MiB以内とする。正式保存には合成PNGとレイヤー付きZIPの両方の保存成功が必要。
- 最大10レイヤー、元に戻す・やり直すは直近50操作。ペンを離した時点とレイヤー操作完了時にIndexedDBへレイヤー構成・履歴を一時保存する。再読み込み時に同じブラウザで復元する。
- 開始時刻・期限はサーバーで管理し、切断・再読み込みでも時間は進む。完成・期限でデータを固定し、保存だけ60秒再試行する。期限後の加筆を完全に検証する仕組みまでは求めない。
- 猶予切れで未保存なら出品・描画ボーナス不可。端末保存は提供するが後日アップロードは認めない。正式保存成功後は端末の一時データを削除する。
- ZIPは全レイヤーPNGと構成情報を含む独自形式。各5MiB・展開後合計50MiBは仮上限として実機検証する。詳細は仕様決定事項2・3章に従う。

### 5.3 出品・公開

- 出品対象はサイト上で描いて保存した下書きとする。
- 出品設定ではタイトル・説明・既存タグ・開始価格・開催時間を設定する。開始価格は0以上の整数pt。時間は5・10・15・20分、初期値10分とし、イベント終了まで確保できない出品を拒否する。
- 作者が出品を確定すると作品を公開し、オークションを開始する。予約開始はVer0.5対象外とする。
- 1作品につきオークションは最大1件とし、Ver0.5では再出品を行わない。
- 最低落札価格は使わない。出品者が希望する最低額は開始価格で設定する。
- 取消機能はVer1で実装する。Ver0.5では出品や入札を取り消す操作を提供しない。

### 5.4 手動入札・ポイントの消費と返却

- 商品詳細画面内で金額を入力・確認・確定する。専用の入札画面は設けず、成功後は同じ画面で最新価格と結果を表示する。
- 入札は開催中かつ終了日時前に限る。出品者本人の入札は認めない。
- 入札額は現在価格より大きく、入札に必要なポイント残高を満たすことを条件とする。開始時の現在価格は開始価格とする。
- 最小上乗せ幅は1pt。最高入札者自身の増額は差額だけ消費する。ロック取得後のサーバー時刻が終了日時以上なら拒否し、自動延長はしない。手動入札確認後に価格が変わった場合は再確認する。
- 入札受理時に入札額を残高から差し引く。高値更新時は前最高入札者に、その入札額を返却する。
- 同一オークションへの複数入札を履歴として保存する。
- 残高更新・入札履歴・ポイント取引履歴・現在価格を同一トランザクションで処理し、同時入札による不整合や残高のマイナスを防ぐ。

### 5.5 自動入札

- 入札者が対象オークションと希望する上限額を設定するユーザー機能とする。
- 他人が入札した際に、指定した上限額の範囲で上乗せして入札する。
- 手動入札と同様に、自己入札禁止・終了日時・残高確認・消費と返却のルールを適用する。
- 上限額が同額の場合は、設定日時が早いユーザーを優先する。
- 設定直後から判定し、上限内で勝つために必要な額だけ1pt単位で競り上げる。上限全額は確保せず、実際の入札額だけを消費する。
- 設定時は次の入札額を支払える残高を必須とする（最高入札者は差額）。上限自体は残高を超えてよい。実行時の不足は自動入札停止・本人通知とする。
- 上限変更・停止は可能だが、受理済み入札は維持する。上限を現在の受理済み入札額より低く変更することは拒否する。
- 価格変動が起きているように見せる「吊り上げbot」とは別機能とし、botはVer0.5に含めない。

### 5.6 オークション終了・落札

- 設定した終了日時で入札受付を終了する。描画終了や作者の完成操作ではオークションを終了しない。
- 定期処理で終了対象を処理し、落札者・落札入札・確定額を記録する。確定処理の実行待ちでも終了日時を過ぎた入札は受理しない。
- 受理済みの入札があれば最高入札者が落札する。最低落札価格による不成立判定は行わない。
- 入札がなければ落札者なしで終了する。この場合、入札によるポイント消費はない。
- 落札額は入札時に差し引いているため、落札確定時に同額を再度差し引かない。
- 落札確定時に出品者へ落札額全額を手数料なしで加算し、履歴を保存する。確定待ちは「終了・結果確定待ち」と表示する。
- 公開閲覧は継続し、作者と落札確定済みの落札者だけに原寸PNG・全レイヤーZIPのダウンロードを提供する。ZIPに編集履歴は含めず、非表示レイヤーも渡すことを出品時に明示する。
- 正式保存後のアプリ内編集・差し替えは不可。端末での編集は可能だが、その結果のアップロード・再出品は提供しない。公開画像の複製は完全には防止しない。

### 5.7 ボーナスポイント・チャージ画面

- 条件達成時にボーナスを自動付与する。画面は条件と獲得履歴を表示し、受け取り操作は不要。
- ボーナスポイントは実際の残高へ反映し、入札に使用できる。付与の履歴も保存する。
- 登録1,000ptを1回、初出品300ptを1回、正式保存100ptを日本時間で1日1回とする案を仮データとして保持し、将来再検討する。同じ作品で描画・初出品の両方を付与する案とする。
- チャージ画面・課金／支払い画面は遷移先として用意する。Stripe API連携、テスト決済、実課金、決済によるポイント加算は実装しない。
- 現行の画面設計にある商品詳細からチャージ画面への導線はポイント不足時に限る。チャージ画面ではVer0.5で課金機能が未提供であると分かるようにする。

### 5.8 検索・お気に入り

- 公開作品をタグで検索できる。複数タグの指定はAND条件とする。
- 出品時は初期登録済みのタグから複数選択する。同じ作品への同一タグの重複付与は認めない。
- 作品のお気に入りとオークションのお気に入りを別々に登録・解除できる。
- アカウント画面では作品とオークションのお気に入り一覧を分けて表示する。

### 5.9 通知

- 通知はアプリ内のみとし、メールアドレス・メール配信は使用しない。
- アプリ内通知の一覧・既読状態を管理し、関連する商品詳細へ移動できる。
- 入札受付は出品者、高値更新は前最高入札者、落札確定は落札者・出品者、未落札終了は出品者、取消は関係する出品者・入札者、残高不足による自動入札停止は本人に通知する。
- 確定前の成功通知や再実行での重複通知を防ぐ。課金結果の通知は対象外。

### 6.1 出品の取り消し・再出品（追加仕様）

- 出品者本人は、開催中かつ終了日時前で、受理済み入札がない場合に限り、任意に出品を取り消せる。入札者自身による入札取消は提供しない。
- 管理者は入札後も、開催中かつ終了日時前に限り理由を記録して出品全体を取り消せる。個別入札を取り消して次点を復活させる処理は行わない。
- 取り消し者・日時・理由を記録し、作品・オークション・入札の履歴は削除しない。管理者の取り消し理由は必須とする。
- 管理者による取り消しでは、入札により差し引かれた未返還ポイントを全額返還する。高値更新で返還済みの入札には二重返還しない。対象オークションの自動入札も停止する。
- 入札、取り消し、終了確定が同時に実行されても、状態更新・残高・返還履歴が整合すること。取り消しの再送で返還が重複しないこと。
- 取り消した作品、または落札者なしで終了した作品は作者が再出品できる。新しいオークションを作り、過去の履歴は残す。同じ作品で同時に開催できるオークションは1件とする。
- 落札済み作品は再出品できない。落札後のキャンセルはこの機能の対象外とする。
- 未落札・取消済みは下書きへ戻さず公開履歴に残す。再出品で画像・レイヤーを編集できない。
- 管理者は理由付きで作品を非公開化でき、開催中なら取消・未返還分の返還を行う。落札後は結果を変えず作者・落札者・管理者だけ閲覧可能とする。
- 非公開中は再出品不可。管理者が理由付きで公開を戻した場合も旧競売は再開せず、通常の再出品条件を適用する。

### 6.2 作品制作ライブ配信（追加仕様）

- 配信は作品制作を対象とし、1作品につき1配信、1配信につき1作品とする。配信できるのは作品の作者本人だけとする。
- 配信開始前に、タイトルなどを持つ画像未登録の下書き作品を作成できる。完成時のPNG保存はその作品を更新し、別作品を重複作成しない。出品には保存済み画像を必須とする。
- 下書きの管理・編集は作者だけに許可するが、制作配信と終了後のコメント履歴は未ログインでも閲覧できる。公開配信を理由に非公開の下書き管理画面を公開しない。
- 配信状態は配信前・配信中・一時中断・終了を区別する。切断後10分以内かつ描画期限前・未終了の場合だけ復帰できる。10分超、描画期限、完成操作、イベント終了で終了する。
- 作者が明示的に終了した配信、および自動終了した配信は再開できない。同じ作品に新しい配信を作ることもできない。再出品しても配信枠は増えない。
- 描画期限・完成操作で配信も終了する。保存失敗でも配信は再開しない。配信終了だけで出品・落札を実行することはない。
- 録画の保存・再生は対象外。配信方式・共有範囲・接続／切断検知方法と秒数は未決で、技術選定時に再検討する。キャンバス限定やカメラ・マイクなしとは確定しない。

### 6.3 配信コメント（追加仕様）

- 投稿はログイン済みユーザーに限り、配信中のみ受け付ける。一時中断中・配信前・終了後は投稿できず、復帰した場合は投稿を再開できる。
- 本文は200文字以内・空白だけ不可。同じユーザーは3秒に1件までとする。
- 本人は自分のコメントを削除でき、配信者と管理者はコメントを非表示にできる。コメントの編集機能は提供しない。
- 配信終了後も通常のコメント履歴を保存し、未ログインでも閲覧できる。通常コメントに1か月の保存期限は適用しない。
- 削除・非表示の本文は直ちに一般閲覧から隠す。本文は管理者向けに操作日から1か月保存し、期限到達後に消去する。操作者・操作日時・理由の監査記録は残す。
- 1か月は暦月で計算し、翌月に同日がない場合は月末の同時刻を期限とする。繰り返しの削除・非表示操作で本文の保存期限を延長しない。

### 6.4 追加機能の確認条件

| 対象 | 確認する結果 |
| --- | --- |
| 出品取消 | 入札前は本人が取消可能。入札後の本人操作と終了後の取消を拒否し、管理者は終了前に理由付きで取消可能 |
| 返還・競合 | 管理者取消で未返還分だけ全額返還し、自動入札を停止。入札・終了確定との競合、取消再送でも二重返還しない |
| 再出品 | 取消済み・未落札終了の作品から新規オークションを作成し、履歴を保持。同時開催と落札済み作品の再出品を拒否 |
| 制作配信 | 作者だけが画像未登録の作品を配信でき、PNG保存時も同じ作品を使用。1作品に2件目の配信を作成できない |
| 中断・終了 | 切断後10分以内でも描画期限前だけ復帰可能。期限・完成・イベント終了で終了し、保存失敗でも再開不可。中断中のコメント投稿を拒否 |
| コメント権限 | ゲストは閲覧のみ。本人の削除と配信者・管理者の非表示を許可し、他人の無権限操作と編集を拒否 |
| 保存期限 | 削除・非表示本文は即座に公開対象外となり、操作日から1か月で消去。監査記録と通常コメントは保持。月末・再操作でも期限が正しい |

今回の変更は設計文書に限る。DB設計書・ER図では現行SQLと目標仕様を区別し、SQL・モデルの移行と実装は未実施とする。

## 7. 非機能要件・権限・技術構成

### 7.1 操作性

- 描画、下書き保存、出品、入札の各操作を分かりやすい日本語で表示する。
- スマートフォンやタブレットでも主要操作を行いやすい配置とする。
- 描画の制限時間とオークションの終了日時を混同しないように表示する。

### 7.2 アクセス権限

以下はVer0.5の権限とする。追加機能の作者・管理者・ゲスト・コメント投稿者の権限は6.1～6.3に従う。

| 利用者・立場 | 可能な操作 |
| --- | --- |
| ゲスト | 公開作品の閲覧・タグ検索 |
| ログインユーザー | 描画、自分の下書き閲覧・出品情報の編集・出品、他人のオークションへの入札・自動入札、お気に入り、ボーナスポイント機能、自分の通知・残高の確認 |
| 出品者 | 自分の下書きから出品する。自分のオークションへの入札は禁止。保存後の加筆やVer0.5での取消は不可 |
| 管理者 | DB上の権限は保持できるが、Ver0.5の管理画面は対象外 |

### 7.3 セキュリティ・整合性

- パスワードはハッシュ化して保存し、ログイン状態はセッションで管理する。
- 描画・出品・入札・お気に入り・下書き閲覧・ボーナスポイント画面・個人情報の参照にはログインを必須とする。
- 状態を変更するフォームにCSRF対策を適用する。下書き・通知などは所有者の権限を確認する。
- 入札処理で対象オークション・入札者・前最高入札者をロックし、最新の状態・金額・残高を確認する。
- 取引履歴を保護し、ユーザー・作品・オークションは原則として物理削除しない。
- 時刻はUTCで保存し、画面では日本時間で表示する。
- 秘密情報や接続情報は環境設定で管理し、ソースコードに直接記載しない。

### 7.4 技術構成

| 分野 | 構成 |
| --- | --- |
| サーバー | Python・Flask。Application FactoryとBlueprintで構成する |
| フロントエンド | HTML・CSS・JavaScript。描画にはCanvasを使用する |
| データベース | XAMPPのMariaDB。スキーマ変更はFlask-Migrateで管理する方針 |
| 認証・フォーム | Flask-Login、Werkzeugによるパスワードハッシュ、Flask-WTFによるCSRF対策 |
| 終了処理 | Flask CLIの終了処理をWindowsタスクスケジューラから定期実行する |

| 対象 | 確認する結果 |
| --- | --- |
| 認証・権限 | ユーザー名で登録・ログイン・ログアウトでき、復旧コードが使用・再発行後に無効化される。非公開情報への無権限操作を拒否する |
| 描画 | 4種類の制限時間を選べ、開始後の変更を拒否する。時間切れ・途中完成で固定し、PNG・全レイヤーZIPの両方を保存する。途中復元・50操作の履歴・保存後の加筆禁止を確認する |

| 入札 | 商品詳細内で複数のユーザーが競り上がれる。自己入札・不十分な入札額・残高不足・終了後の入札を拒否する |
| ポイント | ボーナス・落札代金の加算、入札消費・差額・返還の残高と履歴が整合し、再送で重複せず負の残高にならない |
| 自動入札 | 他人の入札に応じて上限額・残高の範囲内で動作し、同額上限時は設定日時による優先順位を守る |
| 終了・落札 | 終了日時以降に入札できず、最高入札者・確定額が記録される。入札なしは落札者なしで終了し、ポイントを二重に差し引かない |
| 検索・お気に入り | タグAND検索と、作品・オークションそれぞれのお気に入り登録・解除・一覧表示ができる |
| 通知 | 合意した契機・対象者へアプリ内通知し、既読状態を記録する。メールは使用しない |
| 課金画面 | 遷移先を表示できるが、Stripe通信・決済・課金による残高変更は行わない |

## 9. 未決事項・仮値・運用条件

未決・仮値は[仕様決定事項10章](仕様決定事項-2026-10-26.md)に集約する。

| 区分 | 内容 |
| --- | --- |
| 未決・技術検証 | 配信方式、共有範囲、接続・切断検知の方法と秒数 |
| 仮データ | ボーナスの付与量・条件・回数。将来再検討する |
| 仮上限 | レイヤーPNG各5MiB・展開後合計50MiB。実機で検証する |
| 仮性能目標 | 登録100人・同時利用20人、通常操作2秒以内。配信数の負荷は別途測定 |

アプリは1日開催。イベント終了時刻と約2時間後の停止目安を設定可能にする。
終了で新規登録・描画開始・出品・再出品・配信開始を停止し、配信終了と競売確定を行う。
停止まではログイン・閲覧・ダウンロードを提供し、最後の確定処理が完了してから停止する。
競売価格・入札履歴・通知は3秒以内、コメントは1秒程度で更新する目標とする。
DB・作品・取引・監査記録は終了時に一括削除せず保持し、停止後も期限付きコメント本文の消去処理を実行する。
旧想定の作品100件・履歴5,000件の負荷データ内訳は試験設計で具体化し、性能達成済みとは扱わない。
