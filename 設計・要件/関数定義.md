# 関数定義

最終更新日: 2026/10/26

## 1. 本書の対象

Python・Flaskで実装するHEWの命名規則と、機能ごとに使用する関数名を定義する。
[要件定義書](要件定義書.md)と[ロジック・ファイル構造](ロジック-ファイル構造.md)を基に、Ver0.5の基本機能と追加仕様を区別する。
以下は実装用の設計であり、関数が実装済みであることを示さない。引数・戻り値の型やURLの詳細は実装時に具体化する。

2026/10/26確定：登録・ログインにはユーザー名とパスワードを使用する。メールアドレスは登録・認証・通知を含め一切使用しない。関連資料に異なる記述がある場合も、本方針を優先する。

Q1〜Q45の合意・仮値・未決技術課題は[仕様決定事項](仕様決定事項-2026-10-26.md)を参照する。以下の定義も同合意に合わせた設計である。

既存の構成では、主な配置先は[kakusyon/app](../kakusyon/app/)とする。表内の配置先はこのディレクトリからの相対パスであり、「新設予定」はまだ存在しないファイルを表す。
描画などブラウザ内のJavaScriptにはPythonのPEP 8を直接適用せず、ここではサーバー側の関数を定義する。

## 2. 命名規則

### 2.1 Python共通の規則


| 対象 | 規則 | 本プロジェクトでの例 |
| --- | --- | --- |
| パッケージ | 短い英小文字。アンダースコアは避ける | `artworks`、`auctions` |
| モジュール・Pythonファイル | 英小文字。必要に応じてアンダースコアで区切る | `auction_service.py` |
| クラス | 単語の先頭を大文字にするCapWords | `LiveStream`、`StreamComment` |
| 例外クラス | CapWords。エラーを表す場合は末尾に`Error`を付ける | `InsufficientPointsError` |
| 関数・メソッド | 英小文字とアンダースコアのsnake_case | `place_bid`、`save_draft_assets` |
| 変数・引数 | snake_case | `auction_id`、`bid_amount` |
| 定数 | 英大文字とアンダースコア | `ALLOWED_DRAWING_DURATIONS` |
| 型変数を使う場合 | CapWords | `ArtworkType` |
| 非公開の関数・属性 | 先頭にアンダースコアを1つ付ける | `_validate_bid` |
| インスタンス・クラスメソッドの第1引数 | それぞれ`self`・`cls` | `def get_id(self):` |

- 識別子にはASCIIの英単語を使い、意味が分かりにくい省略やローマ字の日本語を避ける。
- `l`・`O`・`I`だけの名前は避ける。組み込み名を隠す`list`・`str`なども使わない。
- 予約語と衝突する場合は末尾に`_`を付ける（例: `class_`）。
- 先頭の`_`は内部利用を表す慣例であり、アクセス制御そのものではない。
- `__name`は継承時の名前衝突を避ける必要がある場合に限る。独自の`__name__`は作らない。
- 既存の公開関数は名前だけを理由に変更せず、呼び出し元やFlaskのエンドポイントへの影響を確認する。

### 2.2 HEWで統一する関数名

次の動詞や用語は、PEP 8そのものの要件ではなく、本プロジェクトでの取り決めとする。

| 形式 | 意味 | 例 |
| --- | --- | --- |
| `show_対象` | 画面を表示するルート関数 | `show_auction_detail` |
| `get_対象` | 1件の情報を取得する | `get_point_balance` |
| `list_対象の複数形` | 一覧を取得する | `list_user_drafts` |
| `create_対象` | データを新規作成する | `create_draft` |
| `update_対象` | 既存情報を更新する | `update_display_name` |
| `save_対象` | ファイルなどを保存する | `save_png` |
| `add_対象`・`remove_対象` | 関連付けを登録・解除する | `add_artwork_favorite` |
| `is_状態`・`has_対象`・`can_操作` | 真偽値で判定結果を返す | `can_resume_stream` |
| `validate_対象` | 条件を検証し、不正なら例外で拒否する | `validate_png` |
| 業務上の動詞＋対象 | 入札・返還・終了などの操作を実行する | `place_bid`、`refund_bid_points` |

用語は、作品=`artwork`、下書き=`draft`、出品・競売=`auction`、入札=`bid`、ポイント=`points`、お気に入り=`favorite`、制作配信=`stream`、配信コメント=`comment`に統一する。DBの既存テーブル名とは区別する。
単体は単数形、一覧は複数形、識別子は`user_id`・`artwork_id`のように`_id`で表す。
時刻は`ends_at`・`disconnected_at`、時間の長さは`duration_seconds`のように区別する。

ルート関数はリクエストの受付・認証・入力変換・応答を担当し、サービス関数は業務処理を担当する。
ルートからサービスを呼び出す場合は、`auction_service.place_bid(...)`のように所属を明確にする。
同じ名前を異なるモジュールに定義してもよいが、同一モジュール内では重複させない。

### 2.3 関数定義時の書式

[PEP 8](https://peps.python.org/pep-0008/)に従い、インデントはスペース4つ、トップレベルの関数間は空行2行とする。
コードは原則1行79文字以内、コメント・docstringは72文字以内とする。
関数には目的を記述し、必要に応じて引数・戻り値・例外・DB更新範囲もdocstringに記載する。

```python
def can_resume_stream(stream, now):
    """中断した配信が復帰可能な状態と期限にあるかを返す。"""
    ...
```

| `services/layer_service.py`（新設予定） | `validate_layer_assets` | 最大10レイヤー、寸法、構成情報、各画像と展開後合計の容量を検証する |
| 同上 | `save_layer_archive` | 全レイヤーPNGと名前・順序・表示・不透明度をZIPとして保存する。編集履歴は含めない |

キャンバスは1,024×1,024px、合成PNG5MiB以内。レイヤーPNG各5MiB・合計50MiBは実機検証前の仮上限とする。
保存猶予内は固定データだけ再送可能。猶予切れは出品・描画ボーナス不可とし、端末保存を提供する。
ブラウザ側の一時保存はペンを離した時点とレイヤー操作完了時に行い、レイヤー構成と直近50操作の元に戻す・やり直す履歴を復元する。
JavaScriptの関数名・データ構造はPythonの命名表と分けて実装時に定義する。正式保存成功後は一時データを削除する。
保存先は公開用画像と権限確認が必要な原寸PNG・ZIPを区別し、ダウンロード専用データを静的URLで一般公開しない。

### 3.3 出品・商品詳細・手動入札・落札

| 配置先 | 関数名 | 処理内容 |
| --- | --- | --- |
| [artworks/routes.py](../kakusyon/app/artworks/routes.py) | `show_listing_form` | 作者に下書きの出品設定画面を表示する |
| 同上 | `publish_auction` | 出品情報を受け付け、サービスへ出品を依頼する |
| [auctions/routes.py](../kakusyon/app/auctions/routes.py) | `show_auction_detail` | オークションIDで作品・価格・履歴・入札結果を表示する |
| 同上 | `submit_bid` | 商品詳細内の入札フォームを受け付ける |
| [services/auction_service.py](../kakusyon/app/services/auction_service.py) | `create_auction` | 作者・保存済み画像・開始価格0以上・終了日時・タグを検証して公開し、競売を開始する |
| 同上 | `place_bid` | 開催状態・期限・本人入札禁止・金額・残高を検証し、入札を確定する |
| 同上 | `_validate_bid` | ロック取得後の最新状態に対して入札条件を検証する内部関数 |
| 同上 | `refund_bid_points` | 高値更新で前最高入札者の未返還ポイントを返還する |
| 同上 | `close_auction` | 期限到達済みの1件を確定し、落札者・落札入札・確定額または入札なしの結果を記録する |
| 同上 | `close_expired_auctions` | 終了対象を抽出して`close_auction`を実行する |

`place_bid`は、残高の減算・前最高入札者への返還・入札履歴・ポイント取引履歴・現在価格を同一トランザクションで更新する。
`refund_bid_points`は呼び出し元のトランザクションに参加し、独立してコミットしない。
終了確定は繰り返し実行しても二重処理せず、入札時に消費した額を再度差し引かない。最低落札価格は使わない。
`create_auction`は5・10・15・20分（初期値10分）を受け付け、イベント終了まで確保できない出品を拒否する。
`place_bid`は最小1pt上乗せ、最高入札者自身の増額は差額消費とする。ロック取得後のサーバー時刻で期限を確認し、手動確認後の価格変更には再確認を求める。
`close_auction`は出品者への全額加算（手数料なし）と履歴を一度だけ確定する。確定待ちは入札不可・落札者のダウンロード不可とする。

### 3.4 自動入札

| 配置先 | 関数名 | 処理内容 |
| --- | --- | --- |
| [auctions/routes.py](../kakusyon/app/auctions/routes.py) | `set_auto_bid` | ログインユーザーの自動入札上限額を受け付ける |
| [services/auction_service.py](../kakusyon/app/services/auction_service.py) | `configure_auto_bid` | 対象競売・本人入札禁止・上限額を検証して設定を保存する |
| 同上 | `process_auto_bids` | 他者の入札時に上限額の範囲で競り上げ、同額上限では先に設定したユーザーを優先する |
| 同上 | `_select_auto_bid_candidate` | 上限額と設定日時から次の入札候補を選ぶ内部関数 |
| [auctions/routes.py](../kakusyon/app/auctions/routes.py) | `stop_auto_bid` | 本人の設定を停止する。受理済み入札は取り消さない |

自動入札にも`place_bid`と同じ残高・期限・消費・返還の条件を適用する。手動入札と自動入札を一連の整合した処理にし、再帰呼び出しによる無限実行を避ける。
設定直後に判定し、勝つために必要な額だけ1pt単位で上げる。上限全額は確保せず、次の入札に必要な残高を設定時に確認する。
上限変更・停止は可能だが、受理済み入札額より低い上限への変更は拒否する。実行時の残高不足は停止・本人通知とする。吊り上げbotは対象外。

### 4.1 出品取消・再出品

| 配置先 | 関数名 | 処理内容 |
| --- | --- | --- |
| [auctions/routes.py](../kakusyon/app/auctions/routes.py) | `cancel_own_auction` | 出品者本人の取消要求を受け付ける |
| [admin/routes.py](../kakusyon/app/admin/routes.py) | `cancel_auction_as_admin` | 管理者の理由付き取消要求を受け付ける |
| [services/cancellation_service.py](../kakusyon/app/services/cancellation_service.py) | `cancel_auction` | 開催中かつ終了前を確認し、権限に応じた取消と操作履歴を記録する |
| 同上 | `refund_unreturned_bid_points` | 未返還分だけ全額返還し、取消再送でも二重返還しない |
| 同上 | `disable_auction_auto_bids` | 取り消したオークションの自動入札を停止する |
| [admin/routes.py](../kakusyon/app/admin/routes.py) | `hide_artwork` | 理由付きで作品を非公開化し、開催中なら取消・未返還分の返還を依頼する |
| 同上 | `restore_artwork_visibility` | 理由付きで公開へ戻す。取消済み競売は再開しない |
| [artworks/routes.py](../kakusyon/app/artworks/routes.py) | `relist_artwork` | 作者の再出品要求を受け付ける |
| [services/auction_service.py](../kakusyon/app/services/auction_service.py) | `create_relisted_auction` | 取消済み・未落札終了の作品から新しいオークションを作成する |

本人の取消は受理済み入札なしに限る。管理者は入札後も取消可能だが理由を必須とする。
取消・返還・自動入札停止は同一トランザクションで扱い、入札・終了処理とロック順序を統一する。
再出品は保存済み画像を必須とし、落札済み作品と同時開催を拒否する。過去の作品・競売・入札履歴を削除しない。
入札者による個別入札取消の関数は設けない。
未落札・取消済みも公開履歴に残し、下書きへ戻さない。非公開中は再出品不可。落札後の非公開化では取引結果を変えず、作者・落札者・管理者だけ閲覧可能とする。

### 4.2 制作ライブ配信

| 配置先 | 関数名 | 処理内容 |
| --- | --- | --- |
| [streams/routes.py](../kakusyon/app/streams/routes.py) | `prepare_stream` | 作者の画像未登録作品と専用配信を準備する |
| 同上 | `show_stream` | ゲストを含む閲覧者へ配信と公開コメントを表示する |
| 同上 | `start_stream` | 作者の配信開始要求を受け付ける |
| 同上 | `resume_stream` | 作者の再接続要求を受け付ける |
| 同上 | `end_stream` | 作者の明示終了要求を受け付ける |
| [services/stream_service.py](../kakusyon/app/services/stream_service.py) | `create_stream` | 作者と作品を確認し、1作品につき1配信だけ作成する |
| 同上 | `start_stream` | 配信前から配信中へ遷移する |
| 同上 | `pause_stream` | 切断を受けて一時中断と中断開始時刻を記録する |
| 同上 | `can_resume_stream` | 中断から10分以内、描画期限前、イベント終了前かつ未終了かを判定する |
| 同上 | `resume_stream` | ロック後に期限を再確認し、同じ配信を配信中へ戻す |
| 同上 | `end_stream` | 明示終了を記録し、以後の再開を拒否する |
| 同上 | `close_stale_streams` | 中断10分超・描画期限・イベント終了に達した配信を終了する |

10分以内でも描画期限後は復帰不可。描画期限・途中完成でも`end_stream`を呼び、保存失敗で再開しない。終了済み配信の再開や同じ作品への配信追加は認めない。
配信終了だけでは出品・落札を実行しない。共有範囲・配信方式・接続／切断検知と秒数は未決とし、技術選定後に入口を具体化する。

### 4.3 配信コメント・監査・本文消去

| 配置先 | 関数名 | 処理内容 |
| --- | --- | --- |
| [comments/routes.py](../kakusyon/app/comments/routes.py) | `post_comment` | ログインユーザーのコメント投稿を受け付ける |
| 同上 | `delete_own_comment` | 本人による削除要求を受け付ける |
| 同上 | `hide_comment` | 配信者・管理者による非表示要求を受け付ける |
| [services/comment_service.py](../kakusyon/app/services/comment_service.py) | `create_comment` | 配信中であることを確認し、コメントを保存する |
| 同上 | `list_public_comments` | ゲスト向けを含む公開履歴を取得し、削除・非表示本文を除外する |
| 同上 | `delete_comment` | 投稿者本人を確認し、本文を即時に公開対象外にする |
| 同上 | `hide_comment` | 配信者・管理者の権限を確認し、本文を即時に公開対象外にする |
| 同上 | `calculate_body_purge_at` | 最初の削除・非表示から日本時間基準の暦月で1か月後を計算し、UTCで返す |
| 同上 | `purge_expired_comment_bodies` | 期限到達済みの本文だけを消去し、監査記録を保持する |
| 同上 | `get_comment_audit` | 管理者向けの操作記録を取得する。期限到達後の本文は返さない |
| [admin/routes.py](../kakusyon/app/admin/routes.py) | `show_comment_audit` | 管理者にコメントの監査画面を表示する |

投稿判定は配信の中断・終了と整合させる。コメント編集は提供しない。
`create_comment`は200文字以内・空白のみ不可・同じユーザーは3秒に1件を検証する。
削除・非表示では操作者・日時・操作種別・理由を記録するが、本人削除の自由記述理由は必須にしない。
翌月に同日がない場合は月末の同時刻を消去期限とし、再操作で期限を延長しない。
期限前の非公開本文は管理者だけに返し、期限到達後は定期消去待ちでも返さない。通常コメントにはこの保存期限を適用しない。

## 5. 開発・定期実行コマンド

配置先は[commands.py](../kakusyon/app/commands.py)とし、業務処理は各サービスを呼び出す。
Pythonの関数名はsnake_case、CLIのコマンド名はハイフン区切りとする。

| 区分 | 関数名 | CLI | 処理内容 |
| --- | --- | --- | --- |
| 基本 | `register_commands` | なし | アプリにCLIコマンドを登録する |
| 基本 | `seed_users_command` | `flask seed-users` | 開発用ユーザーを準備する |
| 基本 | `seed_tags_command` | `flask seed-tags` | 初期タグを準備する |
| 基本 | `close_auctions_command` | `flask close-auctions` | 終了対象の競売を確定する |
| 追加 | `close_stale_streams_command` | `flask close-stale-streams` | 復帰期限を超えた配信を終了する |
| 追加 | `purge_comment_bodies_command` | `flask purge-comment-bodies` | 保存期限に到達した非公開コメント本文を消去する |

定期処理はWindowsタスクスケジューラから実行する。処理の再実行でも結果が重複しないようにする。

イベント終了では新規登録・描画開始・出品・再出品・配信開始を拒否する。`services/event_service.py`（新設予定）の`validate_event_operation`で操作ごとの受付期限を検証し、開催日時を設定可能にする。
約2時間後の停止までは閲覧・ログイン・ダウンロードを提供する。停止前に競売確定を完了し、停止後もコメント本文消去を実行できる運用とする。

## 6. 実装前に統一する事項

- 配信技術・共有範囲・接続／切断検知の方法と秒数は未決として技術選定時に再検討する。
- ボーナス・レイヤー容量・性能は[仕様決定事項10章](仕様決定事項-2026-10-26.md)の仮値と検証条件を使用し、確定値・検証済みと混同しない。
- 再出品・複数入札・配信・コメントに対応するDB制約とモデル。現在のSQLを対応済みとして扱わない。
- 新設予定のモジュールを実装する場合は、Blueprintとサービスの登録・呼び出しも追加する。
